## Feature 12: Supabase PostgreSQL Migration

### Feasibility: 6/10

The migration is feasible but considerably more complex than the roadmap suggests:

- There are **4 distinct SQLite databases** (not just one 293MB file):
  - `bullhorn_master.db` (426K candidates)
  - `unified_federal_contracts.db` (33K contacts, 19K programs)
  - `bd_graph.db` (63K entities)
  - `bullhorn_past_performance.db` (6K contact intel, 28K notes)
- Migration script exists at `scripts/full_migration_to_supabase.py` targeting **31 Supabase tables**
- Supabase DSN is hardcoded in migration script (security concern)
- Qdrant uses **embedded file mode** across the codebase -- pgvector changes the entire access pattern
- **104 occurrences** of `QdrantClient` across 30+ files, **30+ files** with direct `sqlite3.connect`

### Performance Impact

| Operation | Current (Qdrant Embedded) | After (pgvector) | Delta |
|-----------|--------------------------|-------------------|-------|
| Single vector search | ~2-5ms | ~8-20ms | Slower |
| Batch insert (1000 records) | ~500ms | ~200ms | Faster |
| Filtered search | ~5-10ms | ~10-25ms | Slower |
| Full-text + vector hybrid | Not native | Native | Better capability |
| Concurrent writes | Limited (file locks) | Full MVCC | Much better |

### Zero-Downtime Migration Protocol

**Phase A: Preparation** -- Create Supabase tables, set up pgvector indexes, test migration scripts on copies

**Phase B: Shadow Write (48 hours)** -- Every write to Qdrant also writes to Supabase. Verify consistency.

**Phase C: Dual Read Validation (1 week)** -- Query both backends, log differences, always return Qdrant results to users.

**Phase D: Switchover (<1 second)** -- Set `DB_BACKEND=supabase`. Keep shadow writes to Qdrant for rollback.

**Phase E: Cleanup (30 days)** -- Disable shadow writes, keep Qdrant as read-only backup.

### pgvector HNSW Tuning

```sql
-- Contacts (7,337 vectors)
CREATE INDEX ON bd.contacts USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64);

-- Programs (401 vectors) -- tiny, use ivfflat
CREATE INDEX ON bd.programs USING ivfflat (embedding vector_cosine_ops) WITH (lists = 20);

-- Full bullhorn_master (426K records)
CREATE INDEX ON bd.candidates USING hnsw (embedding vector_cosine_ops) WITH (m = 24, ef_construction = 200);
```

### Effort: XL (not L as roadmap implies) -- ~21 days realistic

## Feature 13: LangGraph Workflow Orchestration

### Feasibility: 8/10 -- MOST FEASIBLE

Significant groundwork already exists:
- `ProductionGraphBuilder` (605 lines) with retry, checkpointing, parallel execution, human-in-the-loop
- **3 production workflows already exist**: `morning_briefing.py` (527 lines, 11 nodes, 5-way parallel gather), `pipeline_manager.py` (488 lines, 11 nodes), `contact_enrichment.py`
- `checkpoint_store.py` provides SQLite-based persistent checkpointing
- LangGraph already in requirements.txt

### Hidden Gotchas
1. **CrewAI inside LangGraph nodes** causes event loop conflicts. Spawn as subprocess, not inline.
2. **18 N8N workflows** must be reverse-engineered -- JSON definitions are opaque without N8N runtime.
3. **APScheduler timezone handling** -- use `CronTrigger(hour=5, timezone='UTC')` explicitly.
4. **Checkpoint store uses SQLite** -- no `langgraph-checkpoint-postgres` exists. May need custom implementation after Supabase migration.

### Effort: M (Medium) -- ~10.5 days

## Feature 14: Docker Production Deployment

### Feasibility: 9/10 -- ALREADY 80% DONE

- Neo4j credentials hardcoded (`NEO4J_AUTH: neo4j/pts_bd_2026`)
- Dockerfile copies specific engine directories but misses some (Engine1, Engine4, Engine6, etc.)

## Key Architectural Recommendations

1. **Do not skip Phase 1 (Repository Pattern).** Features 12, 13, and 15 all depend on it.
2. **Keep Qdrant running alongside Supabase for 30+ days.** Costs ~200MB RAM but provides instant rollback.
3. **Build LangGraph master pipeline BEFORE Supabase migration.** Validate orchestration independently from data layer.
4. **Treat 80% coverage as gradual target.** Cover revenue-critical code first (scoring, program mapper, pipeline output).
5. **Externalize all credentials from docker-compose.yml** -- Neo4j password and Supabase DSN are in plaintext.
