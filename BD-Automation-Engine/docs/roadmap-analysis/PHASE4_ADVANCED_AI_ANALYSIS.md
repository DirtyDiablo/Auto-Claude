## Feature 16: Mem0 Conversational Memory

### Feasibility: 8/10

The hard work is done. `Mem0Manager` and `BDMemoryClient` already exist with:
- Qdrant-backed persistence
- Semantic search and version history
- Scoping by user/agent
- 4 memory types: conversation_summary, entity_fact, action_item, contact_insight

### Remaining Work
1. Unify the two memory subsystems (`memory_layer.py` singleton vs `Mem0Manager`)
2. Inject memory context into the RAG query pipeline
3. Add conversation session management to the API
4. Connect existing `MemoryContext.tsx` dashboard page to live API

### Competitive Advantage: Moderate
GovWin IQ and BGOV are search-and-browse with no conversational memory. Stateful BD conversations where the system remembers prior context is genuinely differentiating for power users.

### Effort: S (Small) -- infrastructure 90% built

## Feature 17: LightRAG Knowledge Graph API

### Feasibility: 7/10 -- HIGHEST DIFFERENTIATION

Substantial infrastructure exists:
- `BDGraphRAG` wraps LightRAG with Neo4j and Qdrant support
- `Neo4jManager` handles connections with pooling and retry
- Graph schema: 9 node types, 22+ relationship types, constraints, fulltext indexes
- `ingestion.py` can bulk-load contacts, programs, jobs, interactions
- Dashboard has `KnowledgeGraph.tsx` page

### The Gap
The current `BDGraphRAG.get_entity_graph()` has fragile internal access (`self.rag._graph_storage`), and relationship extraction uses simple string matching against hardcoded entity names rather than actual graph traversal.

### Why This Matters Most
This is where PTS can genuinely differentiate. No competitor offers relationship-graph navigation for federal BD:
> "GDIT primes on AF DCGS → who are their subs → which contacts work there → what jobs are unfilled → what is the recompete timeline"

That traversal-based intelligence is a fundamentally different product.

### Effort: M (Medium)

## Feature 18: Executive BD Intelligence Dashboard

### Feasibility: 6/10

A dashboard with 15+ pages exists but is analyst-oriented (data tables, search, drill-down). Executives need pipeline velocity trends, win/loss ratios, competitive position heat maps, opportunity funnel stages -- **data that does not currently exist**.

### Key Problem
No deal lifecycle layer. The 8-engine pipeline produces contacts, programs, scores, and playbooks but does not track deal stages, win/loss outcomes, or pipeline velocity.

### Competitive Advantage: LOW
GovWin IQ, BGOV, and Salesforce Gov Cloud already have dashboards. Competing on "better dashboard" is a losing proposition. Differentiation comes from data source uniqueness (job posting intelligence), not the dashboard itself.

### Effort: L (Large)

## Feature 19: Enhanced CrewAI Multi-Agent Workflows

### Feasibility: 7/10

CrewAI integration is already substantial:
- `BDCrewOrchestrator` with 8 agents and `FallbackOrchestrator`
- 3 crew factories: BD Research, Weekly Intel, Contact Outreach
- Pydantic output models

### Critical Gap
CrewAI agents do NOT currently have access to Qdrant, Neo4j, or Bullhorn data as tools. The agents are LLM-only without data retrieval tools. This is the single most important fix.

### Competitive Advantage: HIGH
No competitor offers multi-agent BD analysis. A "capture strategy crew" that researches the program, identifies competitors, maps contacts, and drafts an outreach plan in one operation is genuinely novel.

### Effort: M (Medium)

## Feature 20: Multi-Portfolio Expansion

### Feasibility: 4/10 -- DEFER

Everything is DCGS-specific:
- **Scoring**: Hardcoded DCGS program boosts, location boosts, clearance mappings
- **Knowledge base**: Hardcoded entity extraction for DCGS-related terms
- **CrewAI agents**: Reference "DCGS portfolio" in backstories
- **Contacts**: 7,337 contacts primarily in DCGS/ISR community

GBSD (nuclear ICBM, ~$100B) and JADC2 (cross-domain C2) require fundamentally different domain knowledge, contractor ecosystems, clearance requirements, and skill sets.

### Recommendation
Perfect DCGS first. Extract a portfolio-agnostic framework. Then expand. DCGS alone is $950M -- fully capture that first.

### Effort: XL (Extra Large) -- essentially rebuilding the pipeline per portfolio

PTS's moat is **"job posting to BD intelligence"** -- no competitor does this. Features that amplify this moat:
- **F17** (Knowledge Graph) -- graph relationships reveal patterns invisible in flat data

- **F16** (Memory) -- cheap infrastructure polish

Features that do NOT amplify the moat:
